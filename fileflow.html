FileFlow

Guided project document filing

A local Python application that turns an existing folder structure and naming convention into a simple drag-and-drop filing workflow.

The problem

Naming a project document correctly can mean remembering the client, project, document type, version format and destination folder.

Even with a documented convention, that creates repeated decisions, inconsistent filenames and occasional misfiling.

What I built

I built FileFlow to turn those rules into a guided workflow for consistent project documents.

FileFlow uses the destination folder as structured context. It combines project details, document type and configurable naming rules to suggest a suitable filename.

Users retain final control: they can review and edit the suggestion before the document is filed.

FileFlow does not infer a naming convention on its own. Before use, its configuration maps the relevant parts of an existing folder hierarchy to filename fields and naming rules. Once configured, it can adapt to different folder structures, including complex project, grant, client or sales hierarchies.

Why a rules-based approach

FileFlow deliberately uses configured rules rather than AI to make filing decisions. The folder hierarchy already contains the structured context needed to generate a filename, and the result needs to be consistent, explainable and easy to validate.

AI could be useful around the edges, for example helping to define a configuration or suggest a document type, but it is not necessary for the core workflow. In this case, explicit rules provide a more reliable and auditable outcome while the user retains final control.

The workflow

1. The user selects a project and drops a file onto its destination folder.

2. FileFlow offers the relevant document types and generates a suggested filename from the folder path.

3. The user reviews the name, makes any required edits, and files the document.

Built-in safeguards

FileFlow validates filenames, checks for duplicates and restricts filing to configured destinations. The review step keeps the process straightforward without hiding important decisions from the user.

Impact

FileFlow reduces repetitive typing and removes the need for users to memorise detailed naming conventions. The result is more consistent document handling across projects, while users retain final control over each file.

Who it’s for

FileFlow is for teams that still handle files manually but need a dependable, shared way to name and locate them. It works best where a consistent folder hierarchy is practical and people need to find the same kinds of documents in the same places.

That could include departments managing multiple projects, grants, client engagements, sales opportunities or programmes. It can also help an individual bring order to recurring files without adopting a full document-management system.

FileFlow uses the folder path as a source of structured information, applying as much of that context as practical to generate a meaningful filename automatically.

Why I built it

I built FileFlow after seeing how much reliable filing depended on people remembering small details correctly, repeatedly. I wanted to see whether the folder structure could carry more of that burden, so users could focus on the document rather than the mechanics of naming and organising it.

This was not a problem that needed a full document-management system. The existing folder structure already worked; the friction was in applying naming and filing conventions consistently. FileFlow is deliberately lightweight: it supports that process without adding a new repository, complex permissions model or another system for users to learn.
